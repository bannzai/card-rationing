# Card Rationing

カードに 1 回の冒険 (ラン) あたりの使用回数制限があるローグライト・デッキ構築ゲーム。基本の遊び方は Slay the Spire 型 (分岐するマップを進み、ターン制の戦闘でデッキのカードを使う) で、使ったカードの残り回数が戦闘をまたいで減っていく。強いカードほど温存したくなるが、弱いカードだけでは敵を倒せない。このジレンマを冒険全体で考え続けることが遊びの中心になる。

- 起票元: https://github.com/bannzai/IdeaMemo/issues/353
- 判断の根拠 (仮説・判定基準・決めたこと・agent に任せること): [DIRECTION.md](DIRECTION.md)。本文書と食い違う時は DIRECTION.md の「決めたこと」を正とする
- 技術と配布の決定: [ADR 0001](adr/0001-godot-gdscript-steam-desktop-no-backend.md)

## 遊びの核

- カードごとに「1 回の冒険で使える回数」がある。戦闘が終わっても回数は戻らない。山札・手札・捨て札は戦闘ごとに配り直す (戦闘単位) が、残り回数は冒険単位で持つ
- 強いカードほど回数が少なく、弱いカードほど多い
- 冒険の途中のイベントで、回数の回復・不要なカードの削除・強いカードの補充・デッキの入れ替えができる
- キャラクター (冒険者) は複数。物語とラスボスの設定はあるが、ゲーム内で多くは語らず、雰囲気とボス戦前の短い会話で想像させる

## 対象プラットフォーム

PC (Steam): Windows / macOS / Linux。理由と制約は ADR 0001。

## スコープ外

- オンライン機能 (ランキング・アカウント・マルチプレイ)
- 課金 (ゲーム内課金・広告)。Steam での買い切りだけ
- ゲーム内の計測 SDK (ADR 0001)

## 未決

- 使用回数に制限がある自然な世界観 (候補は関門 1 の issue https://github.com/bannzai/card-rationing/issues/2 。決まったら DIRECTION.md「決めたこと」に書く)
- 残り回数が 0 になったカードの扱いと、全カードを使い切った時の扱い (`.claude/rules/card-uses-persist-across-run.md`)
