# 方向性: Card Rationing

## 仮説

Slay the Spire 型のデッキ構築ローグライトを遊ぶ PC のプレイヤーは、ランが最適解に収束して同じになることに飽きている。カードごとにラン全体の使用回数を持たせ、強いカードほど回数を少なくすると、デッキの強さだけでなく「いつ切るか」の判断が毎ランの冒険全体に広がり、先行作 (Deck of Ashes・Nowhere Prophet) が陥った「温存が最適」「速攻一択」「回復作業が面倒」に潰れなければ、そのジレンマ自体が遊ぶ理由になる。

## 判定基準

公開前の判定に使う。Steam のウィッシュリスト・販売数を castle の skill かコマンドで読む経路が無いため、公開後の指標は関門 3 で公開の形を決める時に計測経路と一緒に足す。評価レポートの全文は関門 1 の issue https://github.com/bannzai/card-rationing/issues/2 にある (評価時点のスナップショット。以後の更新は本文書だけに書く)

| 指標 | 計測元 (skill / コマンド) | 継続のしきい値 | 打ち切り条件 | 転換の条件 |
| --- | --- | --- | --- | --- |
| 戦略ごとの 1 幕の踏破率の差 (「状況で使い分ける」bot の踏破率 − 「温存し続ける」「出し惜しみしない」bot のうち高い方の踏破率。各 200 ラン) | `make simulate` (CI の artifact `card-rationing-simulate` の集計 JSON を `gh run download` で取得。ロードマップで作る) | 15 ポイント以上 | 回数と回復量を 2 回調整しても 2 回連続で 5 ポイント未満 | 「温存し続ける」が最も強い → 回数・回復が多すぎるので減らす。「出し惜しみしない」が最も強い → 回数制限が効いていないので強いカードの回数を減らすか敵を強くする |
| 関門 3 (1 幕を通して遊べる触れる版) での bannzai の判断 | 関門 3 の issue への bannzai の返答 (`gh issue view <番号> -R bannzai/card-rationing --json comments`) | 「公開に進む」 | 2 回続けて「ジレンマが面白くない」 | 「温存が面倒」「強いカードを引いても嬉しくない」なら、回数の見せ方・回復の頻度・強いカードの回数を変えて見せ直す |

## 必要な機能

関門 1 で bannzai が判断した一覧 (2026-10-05。過不足の指摘は無く、提案のまま)。

- [ ] ランと使用回数の土台: カードの定義、ラン単位の状態 (デッキ・各カードの残り使用回数・体力・所持金)、ラン途中の保存と読み込み
- [ ] 戦闘: ターン制 (エネルギー・ドロー・敵の行動予告・攻撃・防御)、使ったカードの残り回数が減る、残り 0 のカードの扱い、勝敗
- [ ] マップと報酬・イベント: 分岐する道 (戦闘・強敵・イベント・契約を更新する地点・店・ボス)、契約を更新する地点 (回数の回復) を先まで見せる、戦闘後のカード獲得、使用回数の回復・カードの削除・強いカードの補充・デッキの入れ替え
- [ ] 画面の流れ: タイトル・ラン開始 (冒険者の選択)・敗北・踏破・設定 (音量)・途中から再開
- [ ] 1 人目の冒険者の 1 幕分の中身: 初期デッキ、カード 25〜30 種、敵 6〜8 種、強敵 2 種、ボス 1 体、ボス戦前の短い会話
- [ ] 自動テストプレイ: 戦略 bot (温存し続ける・出し惜しみしない・状況で使い分ける) で 1 幕を headless で回して踏破率を集計する `make simulate` と、1 幕を通して遊ぶ描画付きの録画 `make playtest`
- [ ] 関門 2 で決めた見た目の反映と、BGM・効果音
- [ ] 2 人目以降の冒険者と 2・3 幕 (関門 3 の後)
- [ ] Steamworks 連携 (別 ADR を書いて GodotSteam で実績・クラウドセーブ) と Steam のストアページ (関門 3 で公開に進む返答の後)

## デザインの方向

関門 2 の出し直し (2026-10-06) で bannzai が選んだ方向は「蝋と灯火」。基準にする参考画像は `documents/design/art-reference-2026-10-06/candle-play-1.png` (戦闘) と `candle-title-1.png` (タイトル)。生成に使ったプロンプトは同じディレクトリの `references.json` にあり、絵を足す時は同じ言い回しから始める。

- 画風: 筆の跡が残る手描きの暗いファンタジー。夕暮れの祠の道と蝋燭の光
- 色: 藍と苔色の地に蝋燭の橙。契約の印は封蝋の赤
- 画面の作り: 人物・精霊・敵・背景を絵で見せる。力 (エネルギー) や体力は、枠やバーではなく世界の中の物 (蝋燭・数珠など) で示す
- 残り回数の見せ方: カードに赤い封蝋の列を並べ、使った印は焼けて黒くなる。回数を使い切ったカードは色を失う
- 使わないもの: 平らな矩形の UI パネル、上部のメニューバー、名前を書いただけの矩形、金属・クローム・ネオンの質感、3D レンダ、アニメ調

## agent に任せること

- カードの定義の持ち方 (Resource / JSON 等)、各カードの回数と効果の数値、敵の行動
- 残り 0 になったカードの扱いと、全カードを使い切った時の扱い (決めたら「決めたこと」に書く)
- 世界観「契約の印」の細部 (精霊・英霊の名前と設定、契約者 (プレイヤーキャラクター) たちの設定、ラスボスの正体、ボス戦前の会話の文面)
- 画面の配置と操作 (関門 2 のデザインの方向の範囲で)
- 関門 1〜3 で bannzai が判断しなかった事項。可逆な方を選び、「決めたこと」に記録する
